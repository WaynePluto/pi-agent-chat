# Pi Agent Chat 0.0.10

## Changed

- **Search now reaches collapsed content**: transcript search no longer stops at the fold. Text inside
  collapsed work blocks and folded long messages is matched directly (it stays in the DOM), and card
  bodies that have never rendered — tool output and args, thinking text, notices, compaction summaries,
  `details` payloads — are searched through their underlying data, because a collapsed card's body does
  not exist in the DOM until it is first expanded.

- **Matches in collapsed areas expand layer by layer on navigation**: landing on a hidden match opens the
  work block, then the card (rendering its body), rebuilds the search corpus and re-lands on the first
  visible match inside; a details block nested in that body registers itself on the way, so the next
  Enter opens that layer too. Folded message bubbles unfold the same way. Matches are ordered by document
  position, so next/previous always run top to bottom.

- **Search bar restyled after the VS Code find widget**: the match count moved inside the input (typed
  text never runs under it), and the previous / next / close controls are flat 22×22 icon buttons using
  the official `codicon` glyphs (`arrow-up`, `arrow-down`, `close`) embedded verbatim as local SVG paths —
  no fonts, no network resources.

## Removed

- **The Ctrl+F keybinding and the `piAgentChat.openSearch` command**: a webview's keydown events are
  forwarded to the workbench keybinding service before the page can `preventDefault()` them, so the
  binding could not reliably win over the default editor find in every focus state — Ctrl+F sometimes
  opened the editor's search instead of the chat's. Search is now triggered solely by the header Search
  button, and Ctrl+F returns to pure VS Code default behavior with zero competition from this extension.

## Internal

- Transcript search gained a documented two-layer corpus (DOM text + never-rendered lazy bodies via
  `collectHiddenBodies()`) and a reveal registry (`revealTranscriptElement()`); both live in
  `webview/transcript.ts` and are covered by a new headless scenario asserting that a hit inside a
  collapsed, never-rendered card expands the work block and renders the card body on Enter.
