# Pi Agent Chat 0.0.12

## Fixed

- **The retry button no longer gets stuck on "Retrying..."**: the button's whole lifecycle — offered,
  running, succeeded, failed — is now carried on the notice itself and owned by the host, and the
  button is drawn from that state alone. Before, a successful retry left the card reading
  "Retrying..." forever (nothing ever rebuilds a card that stays on screen), and leaving the session
  and coming back made a spent offer clickable again, because the outcome lived in the clicked button
  instead of in the transcript. A spent offer now shows its outcome on the button; a request that
  fails again closes its turn with a fresh offer of its own.

- **Retry is offered for every interrupted turn, not just one shape of it**: whether a request was
  interrupted is now judged from the session's persisted active branch — the fact the transcript
  shows — instead of agent state alone. This covers turns where Pi's automatic retry already removed
  the failed response from agent state (error → user → error), and requests that threw before
  producing any assistant response, which leave a user message or a tool result at the branch tail.
  The failed response is dropped from agent state only when it is actually still the tail. The early
  refusals (session busy, nothing to re-run) now also end with a state snapshot, so the button never
  waits for an update that never comes; a stale click remains a decision the host takes from the
  session state, never from the button.

- **Disabled buttons show the not-allowed cursor again**: the `button:disabled` cursor rule tied on
  specificity and lost by source order to the later flat-button rules that re-declare
  `cursor: pointer`; a rule at (0,2,1) now holds for every flat button. Visible case: hovering a
  spent retry button still showed the pointing hand.

- **The docs hint is dropped when SYSTEM.md overrides the system prompt**: the empty-session hint
  describes what Pi's default prompt teaches the model, which stops being true once SYSTEM.md
  replaces it. The contradictory warning line is gone too — whoever wrote that file already knows.

## Internal

- New `retry offer lifecycle` self-check in `diagnostics.ts`: it stubs the request, clicks retry
  through a real `ChatBridge`, and pins that the notice goes `running` → `succeeded` and stays
  `succeeded` after a transcript replay. `manual retry` now also covers the error-user-error and
  dangling-user shapes, and the webview smoke test gained a scenario for spent offers
  (`running` / `succeeded` / `failed` buttons).
