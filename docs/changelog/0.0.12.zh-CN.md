# Pi Agent Chat 0.0.12

## 修复

- **重试按钮不再永久停在「重试中...」**：按钮的整个生命周期——可点、进行中、已成功、已失败——改由宿主放在通知上携带，按钮只按该状态绘制。此前重试成功后通知卡片不会重建，文案永远停在「重试中」；离开会话再回来，已消费的重试入口还会重新变成可点击，因为结果记在被点的按钮上而不是 transcript 里。已消费的提议现在把结局留在按钮上；再次失败的请求会带着一个全新的重试提议结束自己那一轮。

- **每一种中断形态都会给出重试入口，而不只是一种**：请求是否被中断改从会话持久化的活动分支判定——那是 transcript 展示的事实——而不再只看 agent state。这覆盖了 Pi 自动重试已把失败响应从 agent state 移除的场景（错误 → 用户消息 → 错误），也覆盖了请求在产出任何 assistant 响应之前就抛出的场景——分支尾部留下的是用户消息或工具结果。只有失败响应确实还在 agent state 尾部时才会被丢弃。提前拒绝的路径（会话正忙、无可重发）现在也会补发一次状态快照，按钮不会等待一个永远不会到来的更新；过期点击仍由宿主按会话状态判定，从不由按钮判定。

- **禁用按钮重新显示禁用光标**：`button:disabled` 的光标规则特异性打平、按源顺序输给了后面重新声明 `cursor: pointer` 的扁平按钮规则；(0,2,1) 的一条规则现在兜住所有扁平按钮。可见案例：重试完成后的按钮 hover 仍显示小手。

- **SYSTEM.md 覆盖 system prompt 时不再显示文档能力提示**：空会话的提示描述的是 Pi 默认 prompt 教给模型的能力，被 SYSTEM.md 替换后不再成立。自相矛盾的警示文案也一并移除——写了该文件的用户本就知情。

## 内部

- `diagnostics.ts` 新增 `retry offer lifecycle` 自检项：打桩请求、经真实 `ChatBridge` 点击重试，钉住通知经历 `running` → `succeeded` 且回放后仍是 `succeeded`。`manual retry` 补充覆盖「错误-用户-错误」与「悬空用户消息」两种形态，webview 冒烟测试新增已消费提议的场景（`running` / `succeeded` / `failed` 按钮）。
