# Pi Agent Chat 0.0.6

## Added

- **HTTP proxy configuration**: the plugin now resolves and installs the global undici
  dispatcher the same way the Pi CLI does. Proxy precedence is environment variables →
  `httpProxy` in `~/.pi/agent/settings.json` → VS Code's `http.proxy`, so the plugin can
  reach the network without ever disagreeing with the CLI. A new `httpIdleTimeoutMs`
  shared-settings entry rebuilds the dispatcher on change. The mirrored SDK logic is
  tagged `SDK-MIRROR:` for easy review on future upgrades.
- **Skill invocation badges**: explicit `/skill:<name>` calls now render with a distinct
  purple badge and bubble border, making them stand out from queued and interjection
  messages in the transcript.
- **Pinned dependency versions**: a `check:dependencies` script asserts that every direct
  dependency uses an exact version, runs as part of `pnpm verify`, and is reused by the
  dependency-update skill.

## Improved

- **Bundled Pi SDK upgraded from 0.83.0 to 0.84.1**, adapting to the new `AuthInteraction`
  auth flow, session creation/switching runtime API, model-picker method signatures, and
  the global HTTP dispatcher. The two Pi packages stay version-locked and ship together.
- Bumped runtime and build dependencies: `undici` 8.8.0 → 8.10.0 (single copy, still
  ≥ 8.7.0 and ≥ the SDK's bundled copy), `diff` 8.0.4 → 9.0.0, `marked` 16.4.2 → 18.0.9,
  `esbuild` → 0.28.2, `typescript` → 6.0.3, `@types/node` → 26.2.0.
- Added a Husky `pre-commit` hook that strips mirror tarball URLs from `pnpm-lock.yaml`.

## Fixed

- User-message badges (queued / interjection / skill) now stack vertically beside the
  message instead of being pushed to the bottom by long content.
- Skill messages no longer lose their queued badge right after the SDK expands the skill
  content: the bridge collapses the skill invocation before emitting queue updates.
- Removed a duplicated skill name in the user skill badge.
