# Pi Agent Chat 0.0.14

## Added

- **Terminal tool (`vscode_terminal`, off by default)**: the agent can now run commands in a
  **visible VS Code integrated terminal you can type into** while they run — answering a prompt,
  confirming an install, hitting Ctrl-C — and everything you type becomes part of the transcript
  the agent reads back. The terminal keeps its shell state (working directory, environment,
  variables) between calls. That combination — you can type, the agent gets the full transcript,
  the chat stays put — is why this tool exists in this host and not as a pi extension.

  - Four interlocking actions: `run`, `list`, `read`, `close`. Terminals are reused across calls
    (creating one costs ~4.3s, reuse ~15ms), never closed automatically, and only terminals this
    tool created can be listed or closed — yours and other extensions' are untouchable.
  - **Shell integration is required**: where VS Code cannot activate it (`cmd`, unusual profiles,
    the feature switched off) the tool refuses to run the command instead of running blind and
    returning an empty success. The terminal created for a refused attempt is cleaned up.
  - **A timed-out command is never killed** — it may be waiting for you to type. The timeout is a
    per-call field (default 30s, hard cap 300s) chosen by the model; when it expires the tool
    reports that the command is *still running* and hands over the output so far.
  - **Output is the screen, not the byte stream**: cursor movements are replayed rather than
    stripped, so line edits and progress bars read the way they look; `read` returns only what is
    new, using the cursor line as the boundary. Full-screen programs (`vim`, `htop`) are out of
    scope. Long output is truncated to the same budget pi's own `bash` tool uses.
  - **Exit codes are exact on POSIX shells only**: VS Code's PowerShell integration reports a
    synthesized code, so on PowerShell the result says *succeeded* or *failed* and nothing more —
    a fabricated `1` would carry meaning the real command never had.
  - **Subagents do not get this tool**: a visible terminal is a shared surface with one person in
    front of it; several lanes typing into it would interleave into something nobody can follow.
    Subagents still have `bash`, which needs no audience.
  - Settings: `piAgentChat.terminal.enabled` / `maxTerminals` (default 3, hard cap 8), both
    `resource`-scoped so a workspace can override them. Changes reach the next session the window
    builds — the same rule as the subagent settings, including the empty-session shortcut that
    rebuilds immediately.
  - An extension registering a same-named tool is always shadowed, on or off, and named in the
    new-session notice. In the Pi CLI, a session containing `vscode_terminal` calls replays as
    generic tool cards with self-explanatory result text; the tool itself is unavailable there.

## Changed

- **The header settings menu now has a single "Plugin settings" entry**: the narrower "Subagent"
  (and the interim "Terminal tool") entries are gone — they only filtered the same settings page
  one level further, and the Settings editor has its own search. New-session hints now point at
  **Settings → Plugin settings** everywhere.

## Fixed

- **Self-checks no longer hardcode `bash`**: the `subagent tool` and `extension reload` checks
  compared against a fixed list of pi's tools, so anyone whose `defaultTools` differs — or who
  installed an extension replacing `bash` — got permanent reds for a configuration choice. Both
  now build their baseline from the session's actual activated tool set.

## Internal

- F5 works out of the box: `.vscode/launch.json` and `tasks.json` are now committed, and the
  `.gitignore` rule was fixed (`.vscode` → `.vscode/*`) so those two negations actually apply —
  git cannot re-include files under an excluded directory.
- A real-machine **terminal spike** command (`Pi Agent Chat: Run Terminal Shell Integration
  Spike`) probes what only a real window, real shell and real human can verify: integration
  activation latency, user-typing capture, incremental delivery, exit-code fidelity. The VT
  replay lives in its own zero-dependency module with built-in cases, shared by the spike and the
  tool, and runs as part of `pnpm verify`.
- New offline self-checks drive the terminal tool through a scripted terminal API to pin its
  refusal paths (no integration, timeout without kill, incremental reads, `close` on foreign
  terminals); the webview snapshot baseline covers the new empty-session notices.
- `engines.vscode` raised to `^1.99.0`: `TerminalState.shell` became available there and
  distinguishes fish/nu/cmd where heuristic probing misreports; the terminal API is unchanged
  between 1.99 and current, so the lowest sufficient version was taken.
