# Pi Agent Chat 0.0.14

## 新增

- **终端工具（`vscode_terminal`，默认关闭）**：agent 可以在**你能看见、也能直接键入的 VS Code 集成终端**里执行命令——回一个提示、确认一次安装、按 Ctrl-C——你键入的一切都会进入 agent 读回的 transcript。终端在多次调用之间保留 shell 状态（工作目录、环境变量、shell 变量）。这个合取（你能敲 + agent 拿到完整 transcript + 聊天界面不消失）正是该工具出现在这个宿主、而不是以 pi 扩展形式存在的理由。

  - 四个互相咬合的动作：`run`、`list`、`read`、`close`。终端跨调用复用（新建约 4.3 秒、复用约 15 毫秒）、绝不自动关闭，且只有本工具创建的终端能被列出和关闭——你手开的、其他扩展的终端一概碰不到。
  - **依赖 shell integration**：VS Code 无法激活它时（`cmd`、特殊 profile、功能被关），工具拒绝执行命令，而不是盲跑后返回空成功；为被拒尝试创建的终端会随手收掉。
  - **超时的命令绝不 kill**——它可能正在等你键入。超时是模型按调用填写的字段（默认 30 秒、硬顶 300 秒）；到期时工具汇报命令*仍在运行*并交付到目前为止的输出。
  - **输出是屏幕，不是字节流**：光标指令被重放而不是剥离，行编辑与进度条读起来和终端里看到的一致；`read` 只返回新增内容，以光标行为边界。全屏程序（`vim`、`htop`）不在范围内。长输出按 pi 自带 `bash` 工具的同一预算截断。
  - **退出码只在 POSIX shell 下精确**：VS Code 的 PowerShell 集成上报的是合成值，因此 pwsh 下只报*成功/失败*——编造的 `1` 会带上真实命令没有的语义。
  - **子代理拿不到这个工具**：可见终端是只有一个人的共享表面，多路往里键入会交织成没人能跟的东西。子代理仍有 `bash`，它不需要观众。
  - 设置：`piAgentChat.terminal.enabled` / `maxTerminals`（默认 3、硬顶 8），均为 `resource` 级、workspace 可覆盖。变更在窗口构造下一个会话时生效——与 subagent 设置同规则，含空会话立即重建的捷径。
  - 注册了同名工具的扩展无论开关一律被屏蔽，并在新会话提示中点名。Pi CLI 可以打开含 `vscode_terminal` 调用的会话、以通用工具卡片读其自解释的结果文本，但无法调用该工具。

## 变更

- **header 设置菜单只留「插件设置」一个入口**：更窄的「子代理」（以及中间态的「终端工具」）入口已删——它们只是把同一个设置页多过滤一层，而设置界面自带搜索。各处新会话提示统一指路**设置 → 插件设置**。

## 修复

- **自检不再硬编码 `bash`**：`subagent tool` 与 `extension reload` 两项自检此前对着一份固定的 pi 工具清单断言，凡是 `defaultTools` 不同、或装了替换 `bash` 的扩展的用户都会恒红——那是对配置选择的报错。两项改为从会话实际激活的工具集取基线。

## 内部

- F5 开箱即用：提交 `.vscode/launch.json` 与 `tasks.json`，并修复 `.gitignore` 规则（`.vscode` → `.vscode/*`），使那两条例外真正生效——git 无法重新包含被排除目录内的文件。
- 新增真机**终端 spike** 命令（`Pi Agent Chat: Run Terminal Shell Integration Spike`）：探测只有真窗口 + 真 shell + 真人能验证的事实——集成激活耗时、用户键入捕获、增量交付、退出码保真。VT 重放独立为零依赖模块并内置用例，spike 与工具共用同一份，且接入 `pnpm verify`。
- 新增离线自检：以脚本化终端 API 驱动终端工具，钉住其拒绝路径（无 integration、超时不 kill、增量读、`close` 碰别人的终端）；webview 快照基线覆盖新的空会话提示。
- `engines.vscode` 抬到 `^1.99.0`：`TerminalState.shell` 自该版本可用，能区分 fish/nu/cmd，启发式探测则会误报；1.99 到当前版本之间终端 API 无变化，故只取够用的最低版本。
