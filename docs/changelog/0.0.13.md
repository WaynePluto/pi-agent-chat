# Pi Agent Chat 0.0.13

## Added

- **Composer arrow-key history**: ↑/↓ walk back and forward through what you sent in this
  window. The history is per-window and memory-only, capped at 100 entries with consecutive
  duplicates collapsed, and keeps the text you actually typed (with `@` reference chips) rather
  than the expanded body the session file stores. Navigating starts from a stashed draft that is
  restored when you return to the latest slot; leaving a slot writes your current edit back into
  it, and clearing it counts as abandoning it. The keys only trigger while the caret sits on the
  first or last line with no selection — single-line input walks one entry per keypress, while the
  middle of a multi-line draft keeps the arrow keys for caret movement — and never while IME is
  composing, with an open completion panel taking priority and both ends stopping the walk instead
  of wrapping.

- **Resuming a session refills input history from it**: when a session becomes live (attach and the
  ready handshake — the only two paths; lane/preview replays never do), the user messages of its
  current branch are populated into the ↑/↓ history, deduplicated by transcript id, so after a
  resume you can walk back through that session's past questions. Lanes are excluded on purpose: a
  subagent's first "user message" is the task text the main agent wrote, not something you typed.
  This mirrors the CLI's `renderInitialMessages` history population.

- **Settings menu entry for the plugin's own settings**: the header settings menu now has a
  "Plugin settings" item that opens the VS Code settings UI filtered to `piAgentChat`, and the
  former "Open settings file" item is renamed "Edit Pi global settings file" so it says what it
  actually edits.

- **Configurable message folding threshold**: new setting `piAgentChat.transcript.foldLines`
  (default 14, the previous behavior) controls when long messages collapse into a preview; `0`
  never folds. The single threshold scales both the line and the character judgments — long text
  without line breaks counts as one line per ~50 characters. Changing it replays the transcript so
  already-built bubbles re-judge, while manual open/close states and reading positions survive.

## Fixed

- **The latest user message no longer loses its action buttons after an extension command**:
  extension commands (e.g. `/services list`) create a user bubble in the transcript without a
  session entry, which shifted the position-based id mapping and left the newest real message's
  bubble without its "back here / fork / label" buttons. Extension-command bubbles are now marked
  and skipped by the mapping.

## Internal

- The `view state` self-check now also asserts the fold threshold on `ready` and that
  `populateInputHistory` is set on attach/ready but never on lanes; its `postState()` race was
  fixed so it runs headless as part of `pnpm verify`.
- Smoke tests extended for input history (IME, drafts, edit write-back), populate ordering and
  deduplication, threshold `0` and restore, and the extension-command mapping; snapshot baselines
  updated.
