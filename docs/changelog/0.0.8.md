# Pi Agent Chat 0.0.8

## Added

- **Resource panel with an on-demand Tools section**: the panel is now hidden by default
  and toggled from a new header button (between the session tree and settings); it stays
  collapsed when first shown and hides on a second click, and the button is disabled when
  there are no resources or on the sessions page. A new **[Tools]** section lists every
  tool registered for the session — extension-provided tools are clickable to jump to the
  source file, while inactive ones (such as `grep`/`find`/`ls`, off by default) are greyed
  out — answering "did this tool actually take effect?". `ResourceItem` gains `hint`/
  `inactive` fields and `ResourceScope` gains a `builtin` group; `collectResourceSections`
  now takes structured input so it can be reused by offline diagnosis, with a new
  resource-listing spike verifying sections and active state against a real session.

- **Three-state highlighting for tools used this session**: tool rows now read as three
  states — **used this session** (green, bold), **activated** (normal foreground), and
  **registered but inactive** (muted, italic, semi-transparent), each with a tooltip. The
  transcript tool-card creation (shared by live and history replay) records the called tool
  name, reusing the same highlight path as skill loading; skills and tools now share the
  `resource-used` highlight, the old skill-only `skill-active`/`active` classes are removed,
  and `clearActiveSkills` is renamed `clearResourceHighlights`.

- **Extension output in the chat, with prompt/extension usage marking**: `ctx.ui.notify`
  from extensions no longer fires a VS Code toast (single line, truncated, detached from the
  conversation). `PiRuntime.setExtensionNoticeSink()` routes it to `status`/`error` cards in
  the owning session's transcript, auto-folding long messages; notifies emitted during an
  extension command are tagged `scope: "command"`, pinned top-level and expanded, while
  background notifies collapse into the work block to avoid flooding. When no sink is wired
  it still falls back to the native toast rather than dropping the message. A new
  `agent/invocations.ts` parses user input **before** `prompt()` rewrites it to attribute
  prompt templates and extension commands, matching placeholder-free template text exactly
  on replay. The resource panel marks prompts and extensions used this session (green),
  flags failed extension loads as inactive, and drops the non-functional **Themes** section.
  `AGENTS.md`, `ARCHITECTURE.md` and the webview DOM snapshot baseline are updated to match.

## Improved

- **Removed `/shell-path` and `/thinking` commands that the CLI lacks**: the shell path now
  has a single entry point in the header settings menu (`pickShellPath` is now private), and
  thinking level is already covered by the composer chip and settings menu — the CLI folded
  it into `/settings` long ago. The `openPicker` protocol collapses to model-only, and the
  now-unused `noThinkingLevels` copy is removed.

## Fixed

- **Real-time model usage refresh**: token, cache and cost stats are now refreshed after
  every model response is persisted.

- **Prefill the original name when renaming non-current sessions**: the rename input
  previously prefilled the name only for the current session and was empty for others; it
  now reads the original name through `SessionManager.getSessionName()` and writes back
  through the same instance.
