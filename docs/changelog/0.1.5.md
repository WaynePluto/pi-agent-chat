# Pi Agent Chat 0.1.5

## Changed

- Anthropic sessions use message threads: each request sends only the new messages and the
  server continues from the previous reply, falling back to the full request after compaction
  or tool-list changes.
- Eligible prompt caches now stay warm for up to 30 minutes between runs (SDK default
  `cacheWarming` changed from `"streaming"` to `"idle"`).

## Fixed

- The grep tool's `glob` is now matched relative to `path`, not the working directory; a
  leading `./` is ignored instead of matching nothing.
- The read tool streams files instead of loading them whole, so large files no longer run out
  of memory even with `offset`/`limit`; the find tool likewise no longer reads every match
  into memory when `context` is set.
- The edit tool no longer rewrites the line endings of untouched lines in files with mixed
  CRLF/LF endings, and no longer runs out of memory on large files after writing.
- The bash tool's timeout error now also reports the shell's exit code and when it exited.
- Images in steering and follow-up messages are now resized like images in idle prompts
  instead of being sent and saved at full size.
- The find tool returns results on Windows for patterns with Windows separators such as
  `src\**\*.ts`, and no longer reports the limit when exactly `limit` files match.
- OpenAI-compatible models no longer send `"tools": []` when all tools are disabled, fixing
  400 errors from vLLM 0.20+ and LiteLLM.

## Dependencies

- Pi SDK (`@earendil-works/pi-ai` / `@earendil-works/pi-coding-agent`): 1.5.0 → 1.5.1.
- `undici`: 8.12.3 → 8.12.4.
- `marked`: 18.1.3 → 18.2.0.
- Dev dependencies: `jsdom` 30.1.3 → 31.0.0, `sass` 1.107.1 → 1.108.1.

## Internal

- The shipped-runtime package list renames `grok-mermaid` to `lovely-mermaid` (renamed by the
  SDK in 1.5.1).
- SDK-MIRROR audit after the 1.5.1 upgrade: `http-dispatcher`, `builtInExtensions`,
  `isSyntheticPath`, the auto-retry steps, the `/skill:` prefix, and the cli-runtime globals
  are all unchanged; the `cacheWarming` default noted in `activity.ts` is updated to
  `"idle"`.
