# Pi Agent Chat

[English](./README.md) | 简体中文

[Pi Coding Agent](https://www.npmjs.com/package/@earendil-works/pi-coding-agent) 原生运行在你的 VS Code 侧边栏中 —— **无需安装 Pi CLI**。

本插件通过内置的**官方** `@earendil-works/pi-coding-agent` SDK（**v0.84.1**）实现，而非 RPC 方式；agent 循环、工具与 LLM 调用都在扩展进程内完成，无需单独安装 Pi CLI，并直接读写你现有的 Pi 配置与会话。兼容边界划在**数据面**而不是能力面：两个宿主共用同一份文件，但依赖终端 Pi 进程的 CLI 扩展在这里跑不了（见[宿主边界](#宿主边界)）。

- 插件只做 UI 层，agent 能力 100% 来自官方 SDK `@earendil-works/pi-coding-agent`，SDK 已打包进 VSIX —— **无需安装 Pi CLI**。
- 复用 `~/.pi/agent/` 的全部配置（auth、models、settings、extensions、skills、prompts、AGENTS.md）与默认 sessions 目录，可与终端 Pi 互相列出/恢复会话。
- **自动走代理，且不会与 CLI 冲突。** 插件以与 Pi CLI 完全相同的方式安装全局 dispatcher，优先级为：环境变量 `http_proxy` / `https_proxy`（含大写与 `no_proxy` 变体）→ `~/.pi/agent/settings.json` 的 `httpProxy` → VS Code 的 `http.proxy`。前两级**就是** CLI 自己的顺序，VS Code 这一级只填补 CLI 本会直连的空位——所以不必为 pi 单独配置 `HTTP_PROXY` / `HTTPS_PROXY`，也不会改变 CLI 的联网方式。`http.proxyStrictSSL: false` 同样会放宽这些请求的证书校验。
- 内置登录/登出流程：无可用模型时显示认证引导页，支持 OAuth 与 API key。
- 界面中英双语，跟随 VS Code 显示语言。
- Marketplace 提供 Windows x64、Linux x64 和 macOS arm64 的目标平台 VSIX；手动安装时请选择匹配当前平台的文件。

> 注意：不要与终端 Pi 同时恢复（resume）同一个 session，JSONL 追加写无锁会交错。

## 设计哲学

与 Pi 本身一样，本插件保持精简：

- **是 Pi 的另一个宿主，不是 CLI 的前端。** 基于官方 `@earendil-works/pi-coding-agent` SDK 独立开发的 VS Code UI。Agent 循环、工具、LLM 调用、extension/skill 加载全部来自 SDK，未作任何修改；无需安装 Pi 的 TUI/CLI 版本。正因为它是*另一个宿主*，「与 CLI 能力面完全一致」从来就不是可达目标：任何依赖终端 Pi 进程的 CLI 扩展在这里都无法工作。因此兼容边界划在**数据面**，而不是能力面。
- **该兼容的地方严格兼容（数据面）。** 配置、会话、扩展、技能与 agent 角色都放在 `~/.pi/agent/`，与终端 Pi 共享，可直接手工编辑，两个宿主随时能接手对方的会话。VS Code 配置项只用于**这个宿主独有的能力**（目前只有子代理工具）——把它们塞进共享配置只会让 CLI 读到看不懂的键。
- **共享 Pi 生态。** 上下文（AGENTS.md）、skills、extensions、prompt 模板、模型与认证都读同一份配置，行为与 CLI 一致——唯一的例外是依赖终端 Pi 进程的扩展（见[宿主边界](#宿主边界)）；会话可在插件与终端之间互通。UI 本身跟随 VS Code 颜色主题（不使用 Pi 的 TUI 主题渲染）。
- **不堆功能。** 单会话模式、小而克制的功能面，只在真正有益处时接入 VS Code 原生能力（diff 视图、QuickPick、主题颜色）。在 pi 自带工具之外只增加 `subagent` 一个工具，且默认关闭；其余能力全部由 pi 本身或 `~/.pi/agent/extensions/` 下的 pi 扩展提供（与 CLI 共享同一份）。

## 单会话模式（设计理念）

同一时间只有一条任务线在运行，运行期间不允许切换到无关会话或新建会话——但可以以**只读预览**方式打开其他会话查看内容（顶部显示提示条，返回当前会话后才能发送消息）。一条任务线可以同时分叉出多路子代理（见下文），你可以逐路观看、逐路停止，但不能与它们对话——你**只跟主代理说话**。不同 VS Code 窗口（不同项目）之间互不影响。

这是有意为之，不打算支持并行**会话**：

- 稀缺的是你的注意力，不是模型的时间：两个会话就是两份上下文要在脑子里维持，而真正花你时间的是验收。
- 如果有多个任务，更好的方式是把它们写成一个任务列表一次性发给 AI，让它按顺序执行；或者排队逐个来。上下文集中在一个会话里，AI 对全局的把握反而更好。
- 会话运行期间，去喝杯咖啡、伸个懒腰，回来验收结果——比盯着多个并行会话来回切换更高效，也更省心。

**子代理不是这条原则的例外，而是它的推论。** 并行的是**执行**，从来不是对话：依然是一条任务线、一份汇报、一个说话对象。子代理面板没有输入框是故意的——你能看、能停单路，但不能跟它对话，所以“我现在该跟谁说话”从来不会成为问题。这也正是为什么委派能加进来、而并行会话不行：它只放大了机器的工作量，没有放大你要维持的对话数。

整体上，本插件的核心思路就是简洁，并相信大模型自身的发展：agent harness 对大模型的干预越少越好。

## 功能

- 流式 markdown 渲染（marked + DOM 白名单净化，逐帧节流重绘）
- 工具卡片：参数摘要、输出折叠、edit 结果的精简 diff 着色
- edit 结果一键打开原生 `vscode.diff`（反向应用 patch 还原旧内容）与目标文件
- session 新建 / 列表 / 恢复 / 删除，并回放历史会话记录；运行期间可以只读预览其他会话
- session 树导航：标题栏 **Tree** 按钮或 `/tree` 打开 QuickPick，可切换分支、从任意节点 fork、给节点打标签；`/fork` 从历史用户消息分叉（原文回填输入框），`/clone` 原位复制当前 session
- 斜杠命令补全：输入 `/` 弹出候选，覆盖内置命令、prompt 模板、extension 命令与 `/skill:*`，命名与描述对齐 CLI
- 模型与思考等级切换（QuickPick）、中止运行、运行中插话（steer）与排队追加消息（follow-up）
- 供应商登录（OAuth / API key），以及**自定义供应商**入口：打开共享的 `~/.pi/agent/models.json`，每次都带一份新的注释模板——文件为空时写入整份模板，已有内容时插入一条新的 provider 条目（未保存，`Ctrl+Z` 即可撤销）。这里不涉及登录：填好 `baseUrl`、模型 id 与任意 `apiKey`（忽略该字段的接入点填占位符即可）后模型就能被选中。保存文件会重新加载配置、列出新增的模型并说明哪些被隐藏及原因；该文件里定义的供应商在列表中带 🗑 行内操作，可删除整条条目（注释与格式保留）
- 消息区上方固定资源列表（Context / Skills / Prompts / Extensions），与 CLI 启动列表一致
- 启动时回到上次显示的会话（包括「还没说话的新会话」）；没有可恢复的记录或文件已不在时，退回到当前工作区最近的会话
- `@` 项目文件引用：在输入框输入 `@` 模糊搜索工作区文件（默认遵循 `.gitignore`；`Ctrl+→` 切换显示被忽略文件，并标记被忽略文件与敏感文件）；选中的文件显示为可移除的标签（chip），发送时以相对路径纯文本附在消息后，由模型自行 `read`
- 子代理（需手动开启）：一次调用分叉出多路子会话，各自在声明的路径范围内直接改你的工作区，并在主代理的记录里以实时进展行呈现

### 子代理（默认关闭）

一次 `subagent` 调用会同时启动多路彼此隔离的子会话。每一路拿到一个任务和一段**可写路径范围**，各自干活并汇报；主代理等待全部结束，收到一份汇总报告。它的目的是吞吐量，不是省上下文——尽管每一路确实都从干净的上下文开始。

**默认关闭**，因为它确实激进：子代理直接写你真实的工作区，失败只汇报、不回滚。可以从标题栏 **设置 → 子代理** 表单开启——表单第一行先问写到工作区还是用户设置，然后写入下面三个值——也可以自己改配置：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `piAgentChat.subagent.enabled` | `false` | 是否提供该工具 |
| `piAgentChat.subagent.maxSubagents` | `3` | 单次调用的并行上限（硬顶 8）；同时作为 schema 上限发给模型。设为 `1` 即退化成串行委派，写入范围强制依然生效 |
| `piAgentChat.subagent.defaultModel` | *(空)* | 未指定模型的子代理使用的 `provider/modelId`；留空则继承父会话 |

三项都是 `resource` 作用域，因此可以用 `.vscode/settings.json` 在实验项目里打开、在生产仓库里关闭。改动在**下一个会话**生效：会话的工具集在构造时就固定了，静默重建会话会把当前对话扔掉。

**可写范围是强制的，不是建议。** 每一路子代理都必须声明自己可写的路径，形式是目录或文件**前缀**（不是 glob——任何东西开跑之前都必须能*证明*范围不重叠，而两个任意 glob 是否相交一般情况下不可判定）。只要两段范围可能指向同一个文件，整次调用直接被拒；运行中越界的 `edit`/`write` 在文件操作层被拒绝。**读不受限**：子代理必须能读懂它改不了的代码。

**被拒绝是情报，不只是拦住。** 有些改动天生跨切面——改一个函数名，调用方就得跟着改——任何对目录树的划分都关不住它。这种时候汇报会列出该子代理被拒绝的具体文件，主代理据此可以自己收尾、或者下一轮重新切分，而不是只知道「有东西被拦了」。跨切面的活本来就该串行：交给范围覆盖两边的单一子代理，或者先并行、再由主代理统一收口。

**有一个已知缺口：** `bash` 拦不住。shell 命令写不写、写到哪里，不跑就无法判定，所以范围检查与文件记账都看不见它。凡是跑过命令的子代理，汇报里都会明写这一点。

**不会回滚任何东西。** 失败的子代理可能在你的工作区里留下半成品，因此汇报会逐路列出它在停止前实际写过哪些文件、是否提前中止。怎么处理由主代理判断。实践建议：在 git 仓库里用它，半成品才能被检查和丢弃。

**你只跟主代理对话。** 子代理的记录是只读的；主代理卡片里的每一行都可以点开观看，或单独停止（其余各路继续，且汇报里会写明是你停的，主代理才不会好心重开一路）。进入某一路永远是你主动点的，也永远不会被自动弹走——你在看某一路时整体跑完了，只会在返回入口上多一个「有新进展」的标记。这正是[单会话模式](#单会话模式设计理念)在起作用：分头的是执行，不是对话。

**没有角色文件。** 每个子代理的起点只有主代理写的任务 + 它可写的路径，没有别的。`~/.pi/agent/agents/` 下的角色定义在这里**不读取**：那个目录属于 CLI 的 `subagent` 扩展，不属于 pi（SDK 对它没有加载器），消费某一个扩展的私有布局等于把它固化成本窗口的契约。想让子代理按某种方式干活，写进任务里，或者写进你自己的 `APPEND_SYSTEM.md`（两个宿主都会读）。如果「子代理默认模型」设置指向本窗口用不了的模型，子代理会降级到父会话的模型，并在主会话里出现一条提示；不会告诉模型——那不是它选的，它也修不了。模型自己点名的模型则相反：找不到就在启动任何一路之前直接报错。

插件不向 system prompt 注入任何使用策略。工具描述只陈述机制事实；如果你想控制**什么时候**才委派、活儿该怎么切，请写在自己的 `~/.pi/agent/APPEND_SYSTEM.md` 或项目 `AGENTS.md` 里——那些文件 CLI 也会读。真正要紧的约束都表达在工具 schema 上并由代码强制执行，因为 prompt 强制不了任何东西。

### 支持子代理的 Skill

Skill 应检测能力而不是判断具体 UI，否则 CLI skill 可使用 `pi --print` 或自己的降级路径。Pi Agent Chat 不拦截 skill 命令，也不模拟 `pi` 可执行文件。

#### 当你已经有 `subagent` 扩展时

注册了名为 `subagent` 工具的 pi 扩展，**在本窗口中一律被屏蔽**，与上面的 subagent 工具开不开无关。理由就是名字本身：本窗口自带 `subagent` 工具，一个名字在这里只能有一个含义。开关打开时，SDK 的工具注册表把该名字解析成本窗口的工具；关闭时，该名字被整体排除——无论哪种状态，模型都不会碰到扩展的实现。判定只看工具**名字**——不认扩展的名称、路径或能力，也不看它怎么写。该判定是自动的，没有开关，且按工作目录重新计算，因此项目级扩展同样算数。

而且扩展式子代理在这里本来就跑不起来：`ExtensionContext` 没有提供任何开子会话的能力，所以扩展只能通过重新启动 Pi 来委派——而它只能靠自省进程（`process.argv[1]` / `process.execPath`）来定位 Pi。在 VS Code 扩展宿主里，这个自省会落到 VS Code 自己的 `bootstrap-fork.js` 上，而它**确实存在**，于是存在性检查通过、启动了错的程序：退出码 0、无输出、无报错，模型拿着空结果继续推理。屏蔽这个名字不会让你损失任何东西。

你的扩展本身不会被改动，在 Pi CLI 中仍然正常工作（那里的自省是对的）。被屏蔽的工具会在新会话提示里点名，因此这个屏蔽不会静默发生。如果你希望自己的实现在这里也能被调用，把它注册成**另一个工具名**即可。

插件不为它提供兼容垫片。改去 spawn 你 `PATH` 上的 `pi` 意味着要求安装 CLI——而这个插件存在的意义之一正是不要求它——还会带来版本偏移、认证与代理各走一遍，以及一个你看不见的子会话。

这是**唯一**被如此处理的工具名。其他形式的宿主依赖见下文「[宿主边界](#宿主边界)」。

#### 用 Pi CLI 打开含子代理记录的会话

会话文件位于 `~/.pi/agent/`，与终端 Pi 共享，因此含 `subagent` 调用的会话可以在 CLI 里 resume（尽力兼容）。不会出错：

- CLI 没有这个工具，调用会退化为通用工具卡片（工具名 + JSON 参数 + 文本结果），没有专属渲染，`/export` 同理。
- 历史可正常回放并继续；即使有未收到结果的工具调用（例如委派进行到一半时关闭了 VS Code），SDK 也会自动补上合成结果。
- 汇报文本本身是自解释的，脱离工具语境也能读懂每一路做了什么、写了哪些文件。
- 若模型照着历史再次调用 `subagent`，结果取决于那边这个名字指什么：CLI 里装了 `subagent` 扩展的话，模型拿到的是那个工具的 schema 而不是本窗口的，可能对着错的参数报参数错误；没装的话只会得到 `Tool subagent not found`，然后改走其他路径。跨宿主 resume 本就是尽力兼容——见下文「[宿主边界](#宿主边界)」。

真正损失的是父子会话之间的链接：每一路子会话都是**独立**的会话文件（名为 `Subagent: <标题>`），在 CLI 会话列表里与其他会话平铺混排，无法从父会话跳转，也不属于父会话的 session 树。CLI 侧同样无法继续委派。

### 宿主边界

`~/.pi/agent/` 里的扩展、技能与设置与 Pi CLI 共享，两边背后跑的也是同一个 SDK 的同一套 agent loop。但**共享配置 ≠ 共享宿主能力**：本插件是 Pi 的另一个宿主，而不是终端里的 Pi 进程。

大多数扩展对此无感。会受影响的是那些**自省自身进程**的扩展——典型场景是把 Pi 作为子进程重新启动，因为当 Pi 就是当前程序时，`process.argv[1]` 与 `process.execPath` 描述的是 Pi 自己；而在扩展宿主里，它们描述的是 VS Code。这类扩展可能在这里失常，在终端里却完全正常。

插件不会去做通用的自动识别：没有任何地方记录着「这个工具需要终端 Pi」，而猜测意味着去读扩展源码或写死扩展名。`subagent` 被单独处理（见上文），仅因为这个名字归本窗口自己的工具所有——与扩展的实现无关。其他情况下，如果某个扩展工具在这里表现异常、在 CLI 里却正常，请优先排查这一点。


另外照旧：插件正在运行某个会话时，不要在 CLI 里 resume 它——会话 JSONL 是无锁追加写。


## 安装（自用）

```powershell
pnpm install
pnpm package:vsix  # 生成 pi-code-agent-chat.vsix
pnpm install:vsix
```

打包产物只包含运行时必需内容：bundle、样式，以及 `dist/node_modules/` 下的 SDK 包目录（提供 docs/examples/主题等资源路径）、photon-node 与原生剪贴板。Marketplace 会分别发布 Windows x64、Linux x64 和 macOS arm64 的目标平台 VSIX；手动安装时请选择匹配当前平台的文件。

## 开发

```powershell
pnpm install
pnpm build          # dist/extension.js + dist/webview.js
pnpm typecheck
pnpm verify         # 构建产物校验 + 无头冒烟测试
```

在 VS Code 中按 `F5`（Run Extension）启动 Extension Development Host，然后：

1. 打开活动栏的 **Pi Agent Chat** 视图，输入 prompt。
2. 命令面板运行 `Pi Agent Chat: Run Spike Diagnostics` 查看运行时风险点报告。
3. 命令面板运行 `Pi Agent Chat: Run Spike Live Test`（会真实调用 LLM，消耗 token）验证一轮 prompt + 工具调用。

无头冒烟测试（不需要 VS Code，`vscode` 模块被打桩）：

```powershell
pnpm verify                       # 仅静态检查 + 诊断
$env:PI_SPIKE_LIVE="1"; node scripts/smoke_load.mjs   # 额外跑一次真实 prompt
```

- `src/agent/scope.ts`、`src/agent/scoped-tools.ts` — 子代理可写范围：重叠检查、越界拒绝与写入记账
- `src/agent/agents.ts` — `~/.pi/agent/agents/*.md` 角色加载，与 CLI 的 subagent 扩展共用同一份定义
- `src/agent/config.ts` — 插件自有的 VS Code 配置（仅限本宿主独有的能力）
- `src/shared/protocol.ts` — host ↔ webview 消息协议（零依赖）
- `src/webview/` — 前端（无框架，DOM 直操作）

打包与 SDK 适配说明（undici override 原因、`import.meta.url` 注入、OAuth flow 静态注册等）见 `docs/spike-findings.md`。
