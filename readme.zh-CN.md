# Pi Agent Chat

[English](./README.md) | 简体中文

[Pi Coding Agent](https://www.npmjs.com/package/@earendil-works/pi-coding-agent) 原生运行在你的 VS Code 侧边栏或编辑区标签页中 —— **无需安装 Pi CLI**。

本插件通过内置的**官方** `@earendil-works/pi-coding-agent` SDK（**v0.84.2**）实现，而非 RPC 方式；agent 循环、工具与 LLM 调用都在扩展进程内完成，无需单独安装 Pi CLI，并直接读写你现有的 Pi 配置与会话。兼容边界划在**数据面**而不是能力面：两个宿主共用同一份文件，但依赖终端 Pi 进程的 CLI 扩展在这里跑不了（见[宿主边界](#宿主边界)）。

- 复用 `~/.pi/agent/` 的全部配置（auth、models、settings、extensions、skills、prompts、AGENTS.md）与默认 sessions 目录，可与终端 Pi 互相列出/恢复会话。
- **自动走代理，且不会与 CLI 冲突。** 插件以与 Pi CLI 完全相同的方式安装全局 dispatcher，优先级为：环境变量 `http_proxy` / `https_proxy`（含大写与 `no_proxy` 变体）→ `~/.pi/agent/settings.json` 的 `httpProxy` → VS Code 的 `http.proxy`。前两级**就是** CLI 自己的顺序，VS Code 这一级只填补 CLI 本会直连的空位——所以不必为 pi 单独配置 `HTTP_PROXY` / `HTTPS_PROXY`，也不会改变 CLI 的联网方式。`http.proxyStrictSSL: false` 同样会放宽这些请求的证书校验。
- 内置登录/登出流程：无可用模型时显示认证引导页，支持 OAuth 与 API key。
- 界面中英双语，跟随 VS Code 显示语言。

> 注意：不要与终端 Pi 同时恢复（resume）同一个 session，JSONL 追加写无锁会交错。

## 设计哲学

与 Pi 本身一样，本插件保持精简：

- **是 Pi 的另一个宿主，不是 CLI 的前端。** Agent 循环、工具、LLM 调用、extension/skill 加载全部来自官方 SDK，未作任何修改；插件只负责 UI，以及任何宿主都绕不开的那些事（认证对话框、代理、自己的配置项）。兼容边界划在**数据面**：同一份 `~/.pi/agent/`、同一批会话，两个宿主随时能接手对方的工作。VS Code 配置项只用于**这个宿主独有的能力**（目前只有子代理工具）。
- **共享 Pi 生态。** 上下文（AGENTS.md）、skills、extensions、prompt 模板、模型与认证都读同一份配置，行为与 CLI 一致——唯一的例外是依赖终端 Pi 进程的扩展（见[宿主边界](#宿主边界)）。UI 本身跟随 VS Code 颜色主题（不使用 Pi 的 TUI 主题）。
- **不堆功能。** 侧边栏与一个编辑区标签页是两个等价的顶层聊天界面；在 pi 自带工具之外只增加 `subagent` 与 `vscode_terminal` 两个工具，且都默认关闭。其余能力全部由 pi 本身或 `~/.pi/agent/extensions/` 下的 pi 扩展提供（与 CLI 共享同一份）。

## 侧边栏与编辑区会话

聊天 header 保留 6 个直接显示的文字按钮：**新会话、会话列表、会话树、搜索、资源、设置**。切换显示位置只有一个独立入口：VS Code 标题区域右上角的原生 `…` icon。侧边栏中提供**将会话移动到编辑器区域** / **将会话移动到新窗口**；编辑区中提供**将会话移动到辅助侧栏** / **将会话移动到新窗口**。移到辅助侧栏后会关闭来源 editor tab；sidebar/editor 两边都有会话时，先交换 controller，再关闭来源 tab。

两个界面完全等价，可以并行运行彼此独立的会话。**新会话**只作用于点击它的当前界面：若当前 controller 正在运行，它会转入后台继续，当前 GUI 由一个新的 controller 和空会话接管。关闭编辑区标签页同理，只关闭 GUI，不中止尚未结束的 agent。会话列表中选择一个已被后台 controller claim 的会话，可以把它带回当前界面，而不会创建第二个 JSONL writer；后台 runtime settle 后释放，已落盘会话仍可正常恢复。

两个顶层 agent 使用同一个工作区。插件不会创建 worktree、强制串行，也不会检测文件写入是否冲突；请使用 git，并自行判断哪些任务适合并行。每个界面自己的 runtime 忙碌时，仍可在其中只读预览其他未被占用的会话。

**子代理在所属顶层会话里仍然只有一条对话线。** 子代理视图没有输入框：你可以观看或停止某一路，但只与该顶层会话的主代理对话。委派可以放大执行并行度，而不会在同一条顶层会话里增加说话对象。

整体上，本插件的核心思路就是简洁，并相信大模型自身的发展：agent harness 对大模型的干预越少越好。

## 功能

- 流式 markdown 渲染（marked + DOM 白名单净化，逐帧节流重绘）
- 工具卡片：参数摘要、输出折叠、edit 结果的精简 diff 着色
- edit 结果一键打开原生 `vscode.diff`（反向应用 patch 还原旧内容）与目标文件
- session 新建 / 列表 / 恢复 / 删除，并回放历史会话记录；侧边栏和一个编辑区标签页可并行承载独立会话，每个界面运行期间仍可只读预览其他会话
- session 树导航：标题栏 **Tree** 按钮或 `/tree` 打开 QuickPick，可切换分支、从任意节点 fork、给节点打标签；`/fork` 从历史用户消息分叉（原文回填输入框），`/clone` 原位复制当前 session
- 斜杠命令补全：输入 `/` 弹出候选，覆盖内置命令、prompt 模板、extension 命令与 `/skill:*`，命名与描述对齐 CLI
- 模型与思考等级切换（QuickPick）、中止运行、运行中插话（steer）与排队追加消息（follow-up）
- 失败请求的手动重发：只要一轮对话停在没有回来的请求上（自动重试放弃的连接错误、超时、压根不可重试的错误），transcript 末尾就会给出一个**重试**按钮，直接重发同一次请求；不必再打一句「继续」，也就不会在对话和模型上下文里多出一条无关消息。重新打开该会话时会重新给出这个按钮，重载窗口也不会丢
- 供应商登录（OAuth / API key），以及**自定义供应商**入口：打开共享的 `~/.pi/agent/models.json`，每次都带一份新的注释模板——文件为空时写入整份模板，已有内容时插入一条新的 provider 条目（未保存，`Ctrl+Z` 即可撤销）。这里不涉及登录：填好 `baseUrl`、模型 id 与任意 `apiKey`（忽略该字段的接入点填占位符即可）后模型就能被选中。保存文件会重新加载配置、列出新增的模型并说明哪些被隐藏及原因；该文件里定义的供应商在列表中带 🗑 行内操作，可删除整条条目（注释与格式保留）
- 消息区上方固定资源列表（Context / Skills / Prompts / Extensions），与 CLI 启动列表一致
- 分别记住侧边栏与编辑区上次显示的会话（包括「还没说话的新会话」）；VS Code 保留的编辑区标签页可在重载后恢复，文件已不在时安全降级
- `@` 项目文件引用：在输入框输入 `@` 模糊搜索工作区文件（默认遵循 `.gitignore`；`Ctrl+→` 切换显示被忽略文件，并标记被忽略文件与敏感文件）；选中的文件显示为可移除的标签（chip），发送时以相对路径纯文本附在消息后，由模型自行 `read`
- 子代理（需手动开启）：一次调用分叉出多路子会话，各自在声明的路径范围内直接改你的工作区，并在主代理的记录里以实时进展行呈现

### 子代理（默认关闭）

一次 `subagent` 调用会同时启动多路彼此隔离的子会话。每一路拿到一个任务和一段**可写路径范围**，从干净的上下文开始各自干活并汇报；主代理等待全部结束，收到一份汇总报告。它换来的是吞吐量。

**默认关闭**，因为它确实激进：子代理直接写你真实的工作区，且不回滚。从标题栏 **设置 → 插件设置** 可打开本插件的 VS Code 设置页（下面三项都在其中），也可以自己改配置：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `piAgentChat.subagent.enabled` | `false` | 是否提供该工具 |
| `piAgentChat.subagent.maxSubagents` | `3` | 单次调用的并行上限（硬顶 8）；同时作为 schema 上限发给模型。设为 `1` 即退化成串行委派，写入范围强制依然生效 |
| `piAgentChat.subagent.defaultModel` | *(空)* | 未指定模型的子代理使用的 `provider/modelId`；留空则继承父会话 |

三项都是 `resource` 作用域，因此可以用 `.vscode/settings.json` 在实验项目里打开、在生产仓库里关闭。会话的工具集在构造时就固定了，所以改动在**窗口下一次构造会话时**生效：新建会话、切换到其他会话（历史从磁盘重新载入，不会丢）、fork、重载窗口都算。**空会话**是例外：没有任何对话可丢，因此会当场重建、立即生效——这也避免了“已经是空会话、新建按钮又是置灰的”这种死路。

**可写范围是强制的。** 每一路子代理都必须声明自己可写的路径，形式是目录或文件**前缀**（不接受 glob——开跑之前必须能*证明*范围不重叠）。只要两段范围可能指向同一个文件，整次调用直接被拒；运行中越界的 `edit`/`write` 在文件操作层被拒绝。**读不受限**：子代理必须能读懂它改不了的代码。

**被拒绝是情报。** 有些改动天生跨切面——改一个函数名，调用方就得跟着改——任何对目录树的划分都关不住它。这种时候汇报会列出该子代理被拒绝的具体文件，主代理据此可以自己收尾、或者下一轮重新切分。跨切面的活本来就该串行：交给范围覆盖两边的单一子代理，或者先并行、再由主代理统一收口。

**`bash` 拦不住。** shell 命令写不写、写到哪里，不跑就无法判定，所以范围检查与文件记账都看不见它。凡是跑过命令的子代理，汇报里都会明写这一点。

**不会回滚任何东西。** 失败的子代理可能在你的工作区里留下半成品，因此汇报会逐路列出它在停止前实际写过哪些文件、是否提前中止。实践建议：在 git 仓库里用它，半成品才能被检查和丢弃。

**你只跟主代理对话。** 子代理的记录是只读的；主代理卡片里的每一行都可以点开观看，或单独停止（其余各路继续，且汇报里会写明是你停的，主代理才不会好心重开一路）。进入某一路始终由你主动点击——你在看某一路时整体跑完了，只会在返回入口上多一个「有新进展」的标记。这保证了每个顶层会话内部仍只有一条对话线：分头的是执行，不是对话。

**角色写在你的提示词文件里。** 每个子代理的起点是主代理写的任务加它可写的路径。想给它一个角色——或者想控制**什么时候**才委派、活儿该怎么切——写进项目的 `AGENTS.md` 或 `~/.pi/agent/APPEND_SYSTEM.md`，两个宿主里 pi 都会把它们发给模型。如果你已经有一个角色目录——`.claude/agents/` 与 `~/.claude/agents/`（Claude Code）、`.opencode/agents/` 与 `~/.config/opencode/agents/`（OpenCode）、`~/.pi/agent/agents/`（CLI 的 subagent 扩展）——指向它即可，不必重述：

```markdown
## 子代理角色
角色定义在 `.claude/agents/*.md`，一个角色一个文件。
委派前先 `ls` 该目录并 `read` 相关角色：每个文件写明了该角色负责什么、怎么干活。
按角色负责的范围给子代理划可写路径，并在任务里点名它的角色文件，剩下的让它自己读。
```

哪个目录都行，因为这里没有任何东西去解析它——模型只是 `ls` 和 `read` 文件，所以你现有的角色文件原样可用，在本窗口和 CLI 里都是，改角色也不需要动配置项。读不受限，因此子代理能打开自己的角色文件，哪怕它在那附近一个字也不能写。机制上的约束——并行上限、可写范围——则表达在工具 schema 上并由代码强制执行。

**没配角色就没角色。** 委派不依赖这些：`task` 就是子代理拿到的全部交代，而它由主代理在运行时现写——也就是说，没有预先定义角色时，子代理的角色就是主代理当场定的。项目的 `AGENTS.md` 依然生效：每一路子代理都是同一工作目录下完整的 pi 会话，上下文文件、技能与扩展都照常加载。写角色的价值在于让这层交代每次都一致，或者当主代理总把活切得不合你意时把切法固定下来。

**子代理的模型用不了时。** 如果「子代理默认模型」设置指向本窗口用不了的模型，子代理会降级到父会话的模型，并在主会话里出现一条提示。模型自己点名的模型则相反：找不到就在启动任何一路之前直接报错。

#### 当你已经有 `subagent` 扩展时

注册了名为 `subagent` 工具的 pi 扩展，**在本窗口中一律被屏蔽**，与上面的 subagent 工具开不开无关：本窗口自带 `subagent` 工具，一个名字在这里只能有一个含义。开关打开时，SDK 的工具注册表把该名字解析成本窗口的工具；关闭时，该名字被整体排除。判定只看工具**名字**，自动生效，且按工作目录重新计算，因此项目级扩展同样算数。

而且扩展式子代理在这里本来就跑不起来：`ExtensionContext` 没有提供任何开子会话的能力，所以扩展只能通过重新启动 Pi 来委派，而它只能靠自省进程（`process.argv[1]` / `process.execPath`）来定位 Pi。在 VS Code 扩展宿主里，这个自省会落到 VS Code 自己的 `bootstrap-fork.js` 上，而它**确实存在**，于是存在性检查通过、启动了错的程序：退出码 0、无输出、无报错，模型拿着空结果继续推理。

你的扩展本身不会被改动，在 Pi CLI 中仍然正常工作（那里的自省是对的）。被屏蔽的工具会在新会话提示里点名。如果你希望自己的实现在这里也能被调用，把它注册成**另一个工具名**即可。

这是唯一被如此处理的工具名；其他形式的宿主依赖见下文「[宿主边界](#宿主边界)」。

#### 用 Pi CLI 打开含子代理记录的会话

会话文件位于 `~/.pi/agent/`，与终端 Pi 共享，因此含 `subagent` 调用的会话可以在 CLI 里 resume（尽力兼容）。不会出错：

- CLI 没有这个工具，调用会渲染为通用工具卡片（工具名 + JSON 参数 + 文本结果），`/export` 同理。
- 历史可正常回放并继续；即使有未收到结果的工具调用（例如委派进行到一半时关闭了 VS Code），SDK 也会自动补上合成结果。
- 汇报文本本身是自解释的，脱离工具语境也能读懂每一路做了什么、写了哪些文件。
- 若模型照着历史再次调用 `subagent`，结果取决于那边这个名字指什么：CLI 里装了 `subagent` 扩展的话，模型拿到的是那个工具的 schema 而不是本窗口的，可能对着错的参数报参数错误；没装的话只会得到 `Tool subagent not found`，然后改走其他路径。跨宿主 resume 本就是尽力兼容——见下文「[宿主边界](#宿主边界)」。

真正损失的是父子会话之间的链接：每一路子会话都是**独立**的会话文件（名为 `Subagent: <标题>`），在 CLI 会话列表里与其他会话平铺混排，无法从父会话跳转，也不属于父会话的 session 树。CLI 侧同样无法继续委派。

### 宿主边界

`~/.pi/agent/` 里的扩展、技能与设置与 Pi CLI 共享，两边背后跑的也是同一个 SDK 的同一套 agent loop。但**共享配置 ≠ 共享宿主能力**：本插件是 Pi 的另一个宿主。

会受影响的是那些**自省自身进程**的扩展——典型场景是把 Pi 作为子进程重新启动，因为当 Pi 就是当前程序时，`process.argv[1]` 与 `process.execPath` 描述的是 Pi 自己；而在扩展宿主里，它们描述的是 VS Code。这类扩展可能在这里失常、在终端里却完全正常，而且无法提前自动识别：如果某个扩展工具在这里表现异常、在 CLI 里却正常，请优先排查这一点。


另外照旧：插件正在运行某个会话时，不要在 CLI 里 resume 它——会话 JSONL 是无锁追加写。
